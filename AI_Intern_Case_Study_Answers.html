Objective

This case study evaluates basic understanding of AI, problem-solving skills, and ability to design a simple real-world system.

Problem Statement

Design a system that can detect objects (like people, vehicles, etc.) and estimate their distance from a camera.

1. Approach
How would you solve this problem?
  • Built a Streamlit web app (DistVision) with two input modes — image upload and live webcam capture.
  • Object detection via YOLOv8s (80 COCO classes), with an automatic YOLO-World v2 fallback for open-vocabulary detection (flowers, trees, pens, and 41 other extra classes).
  • Distance estimated using a hybrid approach — a similar-triangles formula (40%) blended with an AI-generated depth map from Depth Anything V2 (60%).
What steps will you follow from camera input to final output?
  • Input — user uploads an image or captures a webcam frame in the browser; converted to an RGB array and then to BGR for OpenCV.
  • Object Detection — the frame is passed to YOLOv8s (COCO). If the results are weak or empty (max confidence < 0.40 or average confidence < 0.30), YOLO-World runs automatically as a fallback and its results are merged with the COCO ones (overlap and specificity based de-duplication).
  • Filtering — tiny bounding boxes and detections below the confidence slider are removed.
  • AI Depth Map — if enabled, Depth Anything V2 generates a per-pixel relative depth map for the frame.
  • Distance Calculation — the hybrid pipeline blends the similar-triangles distance (40%) with the scaled AI depth (60%) for every detected object.
  • Output — an annotated image with bounding boxes, class labels, confidence scores and distances, plus a detection table and an optional depth-map visualisation.
2. Distance Estimation
How will you calculate distance?

Primary — Similar-Triangles Formula:

Distance (m) = (Known real-world height × Focal length in px) / Bounding-box height in px
  • A lookup table of approximate real-world heights for ~140 object classes (80 COCO + ~60 YOLO-World extras) is maintained in the codebase; unknown classes fall back to a default of 0.50 m.
  • Focal length defaults to 700 px (typical for a 1080p webcam) and is calibratable in-app: the user measures a reference object's real height and distance, reads its bounding-box height from the detection table, and enters all three — the app then computes focal length = (bbox height × known distance) / known height.
  • AI-Depth enhancement — Depth Anything V2 produces a relative (not metric) depth map. The highest-confidence detection is used as an anchor to scale the relative depth into metres. Final distance = 0.6 × AI-scaled depth + 0.4 × similar-triangles distance.
Which method will you use and why?
  • Similar-triangles — simple, fast, works with any monocular camera, no special hardware.
  • AI depth — adds spatial awareness and differentiates objects that look similarly sized in the image but sit at different real-world depths.
  • Hybrid blend — combines the strengths of both, correcting individual errors and giving more reliable results overall. It is used because a single monocular camera alone cannot resolve true depth ambiguity.
3. Model Choice
Which AI model will you use for object detection?
Purpose Model Size Why Chosen
Object Detection YOLOv8s ~22 MB Fast, 80 COCO classes, clean Python API
Open-Vocab Fallback YOLO-World v2 ~26 MB Detects objects beyond the 80 COCO classes
Depth Estimation Depth Anything V2 ~100 MB State-of-the-art monocular depth, runs on CPU
Why did you choose it?
  • vs. YOLOv5 — YOLOv8 gives higher mAP on COCO and has a cleaner Python API.
  • vs. Faster R-CNN / SSD — YOLO is a single-stage detector and significantly faster; two-stage detectors are too slow for an interactive web app.
  • vs. YOLOv8n (nano) — YOLOv8s trades a small amount of speed for noticeably better accuracy, while still running in real time on CPU.
4. Data
What type of data is needed?
  • Pre-trained model weights only — no custom training data was required. YOLOv8s is trained on COCO (330K images, 80 classes); Depth Anything V2 is trained on large-scale synthetic + real depth data.
  • An object-height lookup table (~140 entries) with approximate real-world heights, e.g. person = 1.70 m, car = 1.50 m.
How will you collect or obtain it?
  • YOLOv8s (yolov8s.pt) — auto-downloaded from Ultralytics on first run.
  • YOLO-World (yolov8s-worldv2.pt) — auto-downloaded the same way.
  • Depth Anything V2 — auto-downloaded from the Hugging Face Hub.
  • User input — images are supplied at runtime via upload or webcam; no dataset collection is needed.
5. Deployment Idea
Where will your system run?
  • Laptop / Desktop — runs locally via streamlit run app.py on any machine with Python 3.9+.
  • Cloud — designed to deploy directly to Streamlit Community Cloud (push the repo to GitHub → connect → deploy); uses opencv-python-headless so no system GUI packages are needed on the cloud VM.

How will you make it efficient?
  • Model caching — all models are loaded once (singleton pattern) and reused across requests.
  • Smart fallback — YOLO-World only runs when the COCO results are weak, avoiding unnecessary computation.
  • Small model variants — YOLOv8s (~22 MB) and Depth Anything V2-Small (~100 MB) are chosen for CPU speed.
  • Lazy imports — heavy libraries (PyTorch, Transformers) are imported only when actually needed.
6. Challenges
Challenge 1 — Inaccurate distance without camera calibration

Problem:

The similar-triangles method needs an accurate focal length; the default value can be wrong for different cameras.

Solution:

Built an in-app calibration tool where the user provides a reference object's known height, distance and bounding-box height; the AI depth model also provides a second, independent estimate, which reduces sensitivity to a single calibration.

Challenge 2 — Detecting objects beyond the 80 COCO classes

Problem:

YOLOv8 alone only recognises 80 classes, so common objects like flowers, trees or pens are missed.

Solution:

Implemented a smart auto-fallback to YOLO-World (open-vocabulary detector) covering 41 extra classes, with a semantic merge pipeline that de-duplicates overlapping detections so the more specific label wins.

Challenge 3 — AI depth gives relative values, not absolute metres

Problem:

Depth Anything V2 outputs relative depth, not real-world distance in metres.

Solution:

The most confident detection's similar-triangles distance is used to anchor the entire depth map to absolute metres — the AI model improves relative ordering between objects while similar-triangles grounds the result in real-world scale.
